# Сравнение отображения с Obsidian — 2026-10-29

Эталон: **Obsidian 1.14.5 / Windows**, отдельный временный профиль и синтетический
vault. Начальная проверка на версии установщика 1.8.10 повторена после штатного
обновления временного профиля до 1.14.5. Личный vault пользователя не открывался
для анализа и не изменялся.

Входы: `tests/fixtures/rendering/Reference.md` и `Target.md`. Фактический текст UI
сохранён в `tests/fixtures/rendering/obsidian-reference-text.json`. Настройки
`app.json` и `appearance.json` пустые (`{}`), сторонних плагинов нет. SHA-256
Reference.md до и после просмотра совпал:
`3155DEBE1D22F0B828B46A037746840C8113339A25908E21265E8DFE89C477EC`.

## Что именно сравнивалось

Начальная проверка через Windows accessibility не позволяла захватывать изображение.
В следующем проходе запущен отдельный **скрытый** профиль Obsidian с локальным
диагностическим портом. Через публичный workspace API переключались только тестовые
файлы этого профиля. Сняты HTML, computed styles и PNG; фокус ОС, мышь и клавиатура
не использовались. Перед чтением проверяется абсолютный путь тестового vault;
собственный процесс завершается после capture. SHA-256 исходника проверяется до/после.

Скрипт: `scripts/capture-obsidian-reference.mjs`; локальные команды:
`node scripts/capture-obsidian-reference.mjs Structures.md` и аналогично `Reference.md`.
Для запуска нужен подготовленный временный профиль из этого сеанса и установленный
Obsidian; в CI скрипт не запускается и не устанавливает приложение.

Эталоны: [Structures](../tests/fixtures/rendering/obsidian-structures.png),
[Reference](../tests/fixtures/rendering/obsidian-reference.png).
Результаты и стили находятся рядом в JSON. Это позволяет проверять отдельные параметры,
но ещё не означает полного попиксельного совпадения всех экранов и тем.

| Конструкция | Наблюдение в Obsidian 1.14.5 | Исправление WebObsidian |
|---|---|---|
| `<LS_BEN>` возле `<u>` | Литерал остаётся видимым | Сохраняется в Source/Live/Reading и HTML |
| Таблицы | `==marked==`, `~~struck~~`, вложенный italic и wiki-alias форматируются | Вместо отдельного regex-рендера ячейки используют общий разбор и sanitizer |
| Код в ячейке | Escape в `a\|b` остаётся частью кода | Сохранён и в CodeMirror, и в общем HTML-рендере |
| Сноски | Live оставляет inline-синтаксис; Reading показывает `[1]`, `[2]` и определения | Reading использует отдельные decorations; Preview/public — тот же HTML-диалект; ссылки и обратные переходы указывают на существующие уникальные ID |
| Callouts | Скрытое тело folded callout отсутствует в читаемом тексте; вложенный callout имеет свой title | AST-разбор HTML и отдельные границы вложенных callouts в Live; public поддерживает мышь и клавиатуру |
| Комментарии | В Reading скрыты; внутри code остаются буквальными | Общая защита контекстов и семантика режимов |
| Section embed | Только выбранный heading и подразделы | Общий выбор fragment в Live/Preview; дополнительный заголовок имени файла убран для fragments |
| Block embed | `#^paragraph` — один абзац; `#^list` — список | Добавлен выбор блока; не раскрывается вся заметка при отсутствующем fragment |
| Один перенос | В Reading `first` и `second` разделены переносом | Web/public используют одинаковый default; HTML API поддерживает strictLineBreaks |
| Таблица в цитате/списке | Остаётся таблицей с контейнером | Диапазоны и разделители берутся из дерева; префиксы `>`/списка сохраняются при тестовых edits/Undo |
| Составной heading path | `#Section#Child` выбирает дочерний раздел нужного родителя | Поддержана последовательная область поиска, включая одинаковые имена под разными родителями |
| Recursive embed | Шесть вложенных заметок, затем файловая ссылка | Зафиксирован тот же предел без бесконечного resolver-цикла |

## Дополнительные проверки

- Одинаковые имена заметок в двух папках проверяются реальным HTTP resolver на
  временном vault: источник передаётся через всю цепочку вложений.
- Сложный YAML, nested sequences, comments и quoted values не передаются простому
  редактору свойств. Показывается исходный YAML; это намеренный fallback, а не полная
  копия панели Properties Obsidian. При просмотре документ не сериализуется заново.
- CommonMark image destinations в `<…>` передаются без обрамления в file API.
- Сноски родителя и повторных вложений не получают дублирующихся ID или `[[1]]`.
  Уже подготовленный HTML вложения вставляется после рендера родителя.
- Санитайзер общий для raw HTML в Live, Preview и public. Разрешены инертные цвета
  span; скрипты, обработчики и опасные URL не включаются ради визуального совпадения.
- Browser fixtures используют production GFM grammar, highlighter, CSS, Live fields
  таблиц/HTML/свойств/сворачивания. Отдельная матрица из 24 сочетаний проверяет
  Source/Live/Reading, light/dark, 390/1200 px, LF/CRLF. Ни переключение, ни движение
  курсора не создают docChanged-транзакций. CodeMirror нормализует окончания строк
  в своём внутреннем документе; это не приводит к записи файла при просмотре.
- Пустые колонки восстанавливаются по разделителям (Lezer не создаёт пустые
  TableCell nodes). Сохранение соседней ячейки не превращает escaped pipe в новую
  колонку; обе ошибки воспроизведены независимым обзором и закрыты регрессиями.
- Измеренные значения Obsidian 1.14.5: текст 16px/24px; H1 25.888px/31.0656px;
  абзацы с margin 16px; таблицы — padding 4px 8px и line-height 20.8px; цитаты —
  border-left 2px и padding-left 24px. Исправлены отличавшиеся параметры web/public
  и таблиц Live. Browser-тест сравнивает реальные computed styles с эталоном.

## Что остаётся открытым

- Полная визуальная матрица на нескольких ширинах и темах; базовые фоновые PNG и
  измерения уже получены. Полный pixel diff приложения ещё не выполнен.
- Расширенные paste/undo-сценарии таблиц, редактирование сложного YAML и block refs
  внутри сложных контейнеров. Базовые tables-in-list/quote, Undo, составные heading
  paths и предел рекурсивных вложений закрыты проверками.
- Полная матрица Mermaid/math/reference links и строгих переносов в интерфейсе:
  существующие проверки сохранены, но независимая сверка всех этих вариантов с
  оригиналом пока не выполнена. strictLineBreaks сейчас параметр HTML API, не новая
  пользовательская настройка.
- Linux CI и deployment: этот этап проверен локально на Windows. На сервер данные
  и сборка не отправлялись.
