# Удалённый MCP для WebObsidian

Дата: 2026-10-30. Статус: реализовано по запросу пользователя; внешняя приёмка HTTPS/Perplexity ещё не проведена.
Запрос: дать Perplexity доступ к серверному хранилищу через HTTPS, сохранить локальный MCP и описать оба варианта.

## Текущее состояние

- `mcp-server/src/index.ts` регистрирует 10 инструментов и запускает stdio.
- `mcp-server/src/client.ts` использует глобальный HTTP-клиент с ключом из окружения; импорт без ключа завершает процесс.
- `/api/v1` проверяет ключи, scopes и лимит запросов; операции заметок используют общую очередь изменений vault.
- Основной Express-сервер работает на порту 8787, TLS завершает reverse proxy. Docker runtime сейчас копирует только сервер и web-артефакты.
- Изменения в рабочем дереве уже затрагивают Agent API, документацию и редактор. При реализации сохранить их; сверять операции с текущим кодом, не восстанавливать старые версии файлов.

## Варианты

| Вариант | Плюсы | Цена |
|---|---|---|
| `/mcp` внутри Express WebObsidian | Один адрес, существующие ключи и лимиты, один контейнер | Вынести операции Agent API из маршрутов в общий сервис |
| Отдельный HTTP MCP-процесс перед REST API | Меньше вмешательства в основной сервер | Ещё один процесс, отдельная проверка ключа на handshake, управление передачей credentials |
| Универсальный stdio→HTTP мост | Быстрый прототип | Дополнительная зависимость и риск общей привилегированной учётной записи для разных клиентов |

Рекомендация автора плана: первый вариант. Выбор предложен для этого запроса, не является утверждением о согласовании или готовой функции.

## Контракт

1. Локальный запуск `node mcp-server/dist/index.js`, `npm run mcp`, переменные `WEBOBSIDIAN_BASE_URL` и `WEBOBSIDIAN_API_KEY` сохраняются. Stdio остаётся стандартным режимом этого entry point; HTTP-порт он не открывает.
2. Новый endpoint основного сервера — `/mcp`, Streamable HTTP. Внешний адрес примера: `https://notes.example.com/mcp`. Он станет рабочим только после реализации, развёртывания и проверки.
3. Включение: `WEBOBSIDIAN_MCP_ENABLED=false` по умолчанию. При выключении `/mcp` отвечает 404, включая GET, и не попадает в SPA fallback.
4. При включении обязательна `WEBOBSIDIAN_MCP_PUBLIC_URL` — абсолютный URL endpoint без credentials/query/fragment. Для удалённого доступа нужен HTTPS; HTTP разрешён только для loopback в локальных тестах. Неверная конфигурация останавливает запуск с понятным сообщением без секретов.
5. Stateless transport: отдельные McpServer/transport и контекст доступа для каждого POST; без session ID, постоянного SSE-канала и межзапросного состояния. JSON-ответы через SDK. Авторизованные GET/DELETE дают 405 с `Allow: POST`; notifications — 202. Проверку MCP-заголовков, версии и JSON-RPC выполняет SDK. Старый HTTP+SSE транспорт в первую версию не входит.
6. Каждый HTTP-запрос аутентифицируется действующим ключом WebObsidian: `Authorization: Bearer <key>` или существующий `X-API-Key`. Cookie браузера не заменяет ключ. Отзыв ключа действует со следующего запроса; уже начатая операция не откатывается.
7. Существующий per-key rate limit общий для REST и MCP; один входящий MCP-запрос списывает одну единицу. Вложенных HTTP-запросов к собственному REST API нет. Неавторизованные запросы — 401, превышение лимита — 429.
8. Все 10 названий, схемы аргументов и успешные результаты инструментов сохраняются на обоих транспортах. Scope проверяется перед выполнением операции независимо от `tools/list`. Недостаток прав при `tools/call` — MCP `isError: true` с обозначением 403, без изменения файлов.
9. Сохраняются `base_version`, строгий режим версий в его фактическом текущем поведении, атомарные правки, корзина, переиндексация и уведомления редактора. Семантику REST, включая ошибки и значения по умолчанию, не менять при выделении общего слоя.
10. Проверять Host по настроенному public URL и явно добавленным локальным тестовым адресам; не доверять произвольному X-Forwarded-Host. Отсутствующий Origin разрешён для server-to-server клиентов. Присутствующий Origin должен совпадать с origin public URL либо точным элементом `WEBOBSIDIAN_MCP_ALLOWED_ORIGINS` (CSV, без wildcard); иначе 403. Не вводить глобальный permissive CORS.
11. TLS и сертификат остаются на reverse proxy. Он сохраняет `/mcp`, Host, Authorization, Content-Type, Accept и MCP-Protocol-Version; не кэширует ответы. Ключи, тела заметок и Authorization не попадают в логи. Ответы `/mcp`: `Cache-Control: no-store`.
12. Закрывать transport/server после завершения ответа, ошибки или disconnect, освобождать ресурсы однократно. Отключение клиента не означает автоматический повтор либо откат записи.

## Структура

`mcp-server` становится одновременно stdio-приложением и библиотекой регистрации инструментов. Новый export `@webobsidian/mcp-server/server` отдаёт `createMcpServer(api: AgentApi): McpServer`; импорт не запускает transport и не читает ключи.

`AgentApi` — типизированный контракт десяти операций из текущего HTTP-клиента. HTTP-клиент создаётся через `createAgentApiClient({baseUrl, apiKey})`, только stdio entry point читает окружение и обрабатывает отсутствие ключа.

В `server/src/services/agentOperations.ts` выделяются текущие операции REST. В `server/src/services/mcpAgentApi.ts` адаптер `createScopedAgentApi(scopes: readonly Scope[]): AgentApi` проверяет scope и вызывает их. REST-маршруты используют тот же сервис, сохраняя HTTP-контракт. Общий слой не зависит от Express и не обходит vault mutation queue.

`server/src/routes/mcp.ts` подключается перед общими маршрутизаторами и SPA fallback. Использует существующий `requireApiKey()` для аутентификации/лимитов, создаёт request-scoped адаптер и MCP-server. Для неизвестных внутренних ошибок возвращает нейтральное сообщение; известные ошибки домена сохраняет.

Сборка mcp-server выполняется до server; библиотека поставляется с `.d.ts`. Docker должен включать библиотеку и её production dependencies. Desktop bundler должен разрешать её экспорт без запуска stdio.

## Perplexity и границы совместимости

В Perplexity выбрать Remote + Streamable HTTP + API Key и дать ключ WebObsidian с `read,search`. Клиентские кредиты Perplexity API для такого подключения не нужны; лимиты подписки и Computer описывать отдельно, без обещания безлимитного доступа.

Документация Perplexity указывает API Key, но не фиксирует на этой странице точную форму исходящего заголовка. До объявления поддержки выполнить реальный handshake с тестовым ключом в Pro: проверить передачу credentials без записи значения в логи. Если фактическая схема не совпадёт с поддержанными Bearer/X-API-Key, уточнить адаптер или документировать ограничение. Не отключать авторизацию для обхода ошибки.

MCP-коннектор требует сервер MCP; адрес `/api/v1` не является MCP URL. Первая версия не добавляет OAuth, отдельные кредиты, новые инструменты или синхронизацию локального vault.

## Критерии готовности

- Старый stdio handshake и все инструменты работают с прежним конфигом, stdout содержит только протокол.
- HTTP initialize → initialized → tools/list → tools/call проходит официальным SDK-клиентом и вручную в Perplexity Pro через HTTPS.
- read/search ключ читает и ищет; попытка записи не меняет vault; отозванный ключ не проходит следующий запрос.
- Параллельные клиенты с разными scopes не разделяют полномочия; REST/stdio/HTTP корректно обнаруживают конфликт версий одной заметки.
- Упакованные Docker и desktop запускаются без MCP-секрета в environment; отключённый HTTP MCP не меняет локальное подключение.
- Документация содержит два способа подключения, настройку TLS, пример Perplexity и диагностику. До реального smoke-test поддержка Perplexity помечена непроверенной.
