# Полный перенос Editing Toolbar: проектное предложение

Дата: 2026-10-29. Статус: проработанный план по запросу пользователя; реализация следующих этапов не начата.

## Цель и источник требований

Расширить встроенную панель WebObsidian до максимально полного функционального аналога Editing Toolbar: команды, раскрывающиеся группы, палитры, диалоги, панель при выделении, расположение и настройка. Пользователь отдельно уточнил наличие всплывающих подпанелей и показал группу редактирования с пятью действиями. Это обязательная часть результата.

Основание: два скриншота пользователя и [исходный проект](https://github.com/PKM-er/obsidian-editing-toolbar). Проверены README, manifest, src/settings/settingsData.ts и src/commands/commands.ts; manifest содержит версию 4.1.11, полученный SHA master — `7f41f8df4edbcb1550bbce03c000b2289c85443f` (2026-10-24). Это исследованный upstream, а не подтверждённая версия установленного у пользователя плагина. Персональный набор пользователя может отличаться.

[Стандартная конфигурация](https://github.com/PKM-er/obsidian-editing-toolbar/blob/7f41f8df4edbcb1550bbce03c000b2289c85443f/src/settings/settingsData.ts) содержит **64 уникальные команды**, если раскрыть подменю и исключить разделители. Реестр содержит также дополнительные действия: комментарии, теги, управление расположением/видимостью, пользовательские команды и AI. Полнота основной поставки измеряется всеми 64 командами плюс описанными ниже возможностями интерфейса; 64 — не число всех возможных команд расширяемого Obsidian.

До реализации зафиксировать исходные файлы именно по SHA и проверить соответствие инвентарю; поведение вспомогательных преобразователей текста ещё требует сверки. Не обещать точную семантику только по названию кнопки.

## Подходы

1. **Нативная панель поверх CodeMirror 6 — рекомендованный подход.** Общий реестр команд, собственные всплытия и адаптация существующего рендеринга. Сохраняет архитектуру приложения и позволяет проверять каждую команду.
2. Запуск исходного плагина через Obsidian compatibility shim потребует App/Workspace/Menu/Modal/Editor API, жизненного цикла и сторонних команд. Объём существенно шире панели, а доступность всех зависимостей не гарантирована.
3. Достраивание отдельных кнопок в текущем FormatToolbar быстро расширит строку, но сохранит дублирование с контекстным меню и не решит вложенность, настройки и работу с выделением.

Пользователь ранее выбрал расширение встроенной панели. Технические решения ниже — предлагаемые значения по умолчанию, а не утверждение об отдельно согласованных деталях.

## Обязательные возможности и взаимодействие

### Верхняя строка и раскрывающиеся группы

Начальная компоновка следует скриншоту: Undo, Redo, кисть, ластик, H2, H3, меню заголовков, Bold, Italic, Strike, Underline, текстовые инструменты, редактирование, вложение, таблица, задачи, цитаты/callout, Markdown, списки, выравнивание, цвет текста, фон, фокус редактора, полный экран рабочего пространства. Highlight также доступен; его положение задаётся конфигурацией.

Не пытаться уместить все 64 действия отдельными иконками. Прямые кнопки исполняют команду. Кнопки групп открывают подпанель. Для цвета основная часть применяет последний цвет, стрелка открывает палитру; у группы без основного действия вся кнопка открывает меню.

| Тип всплытия | Содержимое | Поведение |
|---|---|---|
| Компактная подпанель | Copy, Cut, Paste, строка вниз/вверх, как на втором скриншоте | Пять иконок, подписи в подсказках, доступные названия, один клик на действие |
| Меню группы | H1–H6/обычный текст, списки, Markdown, выравнивание | Иконка + название + shortcut, выбранное/смешанное состояние |
| Вложенное меню | Пользовательские группы и длинные наборы | Открывается в доступную сторону, возврат на уровень выше |
| Палитра | Цвет текста/фона, стандартные/недавние/свои, сброс | Предпросмотр образца; изменение документа только при выборе |
| Диалог | Ссылка, таблица, callout, параметры преобразования | Поля ввода, понятные Apply/Cancel, проверка параметров |
| Панель выделения | Частые действия и раскрывающиеся группы | Следует выделению и остаётся открытой при работе со своим меню |
| Подсказка | Название и shortcut | Не перехватывает фокус, не закрывает рабочее меню |

Контракт всплытий:

- Открытие кликом, Enter/Space; hover показывает подсказку, а не запускает команду. Подменю может открываться при hover после 150 мс; click/touch всегда доступны.
- Одновременно открыта одна ветка меню. Второй клик по той же кнопке закрывает её; выбор другой группы переключает ветку.
- Координатор всплытий один на Workspace; top/following/fixed/mobile являются его клиентами. Открытие меню другой поверхности закрывает прежнюю ветку, сохраняя контекст нового инициатора. Escape обрабатывается координатором один раз.
- Mouse down на обычной кнопке не сбрасывает выделение. Ввод в диалоге получает фокус, исходный диапазон сохраняется отдельным контекстом.
- Перемещение указателя с кнопки в подпанель не закрывает её. Палитра/диалог считаются частью текущего взаимодействия; blur редактора сам по себе их не закрывает.
- Escape закрывает самый верхний слой; затем вложенное/основное меню; только последующие Escape отменяют кисть или режим фокуса. После закрытия фокус возвращается на кнопку/редактор.
- Клик вне ветки закрывает её без применения незавершённого ввода. Переключение документа, уничтожение EditorView или блокировка заметки отменяет ожидающее изменение.
- Меню привязаны к viewport: flip/shift у правого и нижнего края, max-height и прокрутка; пересчёт при scroll/resize/zoom/появлении экранной клавиатуры.
- Portal живёт в корректном theme/fullscreen-root. Меню не обрезаются overflow родителя, видны в тёмной/светлой теме и browser fullscreen.
- Стрелки/Home/End перемещаются по пунктам, вправо открывает подменю, влево возвращает, Enter выполняет, Tab выходит; диалог использует focus trap. ARIA toolbar/menu/menuitem/dialog, pressed/expanded и текст причины disabled.
- На touch нет зависимых от hover действий; цели касания не меньше 44×44 CSS px. На ширине 390 px группы уходят в «Ещё» или ограниченную прокрутку. Native handles выделения остаются работоспособны.

### Команды и документ

Все поверхности используют один реестр: верхняя, фиксированная, мобильная, панель выделения, контекстное меню, Command Palette и существующие горячие клавиши. Никаких новых конфликтующих shortcuts по умолчанию.

Дополнительно к 64 стандартным пунктам включить нативные действия из реестра upstream: вставка тега, переключение комментария Obsidian `%%…%%`, обычный абзац H0, показ/скрытие панели и переключение top/following/fixed. Их можно добавлять в пользовательские раскладки; тестировать отдельно от стандартных 64. Пользовательские команды первой версии — буквальные prefix/suffix-шаблоны, без исполнения скриптов.

Контекст исполнения привязан к конкретным EditorView и документу. Отложенные формы хранят снимок документа и selection; при любом изменении текста до Apply изменение отменяется с предложением повторить действие. Не применять сохранённые offsets к уже другому тексту. Это осознанная простая политика первой версии; mapping через ChangeDesc можно добавить отдельно.

Одна команда — одна операция Undo; исключение только действия без изменения текста. Мультивыделение поддерживается для inline и построчных команд с объединением пересекающихся строк. Структурные вставки и формы с неоднозначным результатом при нескольких диапазонах disabled с объяснением. Пустое выделение: inline работает со словом, если оно есть, иначе вставляет пару маркеров; построчное — с текущей строкой; структурная вставка — в каретку; разрушительные текстовые преобразования требуют явного выделения.

Locked/read-only запрещает запись на уровне исполнения, а не только кнопки. Copy и просмотр подсказок остаются доступны. Состояния активного форматирования определяются по синтаксису и всей выборке; смешанное выделение не обозначается как полностью отформатированное.

Выделенный текст сохраняется при смене H1→H2, bullet→numbered→task, увеличении отступа. Frontmatter, fenced/inline code и содержимое ссылок не переписываются посторонними структурными командами. У каждого преобразования есть точные fixture вход/выход и поведение вне поддерживаемого контекста.

### Формат хранения и рендеринг

- Markdown для bold, italic, strike, highlight, заголовков, списков, цитат, кода, wikilink/embed, ссылок, callout, разделителя, математики.
- Совместимые HTML u/sup/sub и span для цвета. Цвет нормализуется в #RRGGBB или #RRGGBBAA; обе формы разрешены точечно. Произвольные CSS, URL и event-атрибуты не допускаются.
- Выравнивание хранить как ограниченное HTML-представление блока с left/center/right/justify; адаптер также читает известные upstream p align/center. Точную сериализацию зафиксировать round-trip тестом с Markdown внутри до включения команды. Если p ломает Markdown парсер, использовать div с пустыми строками вокруг Markdown, и подтвердить совместимость в Obsidian.
- Все новые формы проходят Source, Live Preview, Reading, split Preview и server public share. Отдельный серверный sanitizer сейчас требует адаптации; совпадение в браузере не доказывает совпадение share.
- Очистка форматирования снимает поддерживаемые inline стили и цвета; сохраняет текст, ссылки с адресами, вложения, структуру блоков и неизвестный HTML. Получение plain text — отдельная команда. Различие с upstream при необходимости явно документировать.
- Кисть копирует поддерживаемое inline оформление и цвета/фон, без ссылок и структуры блока. Один клик — одно применение к следующему выделению; двойной — удержание до Escape/выключения. Для mixed-источника копировать только общие стили. Пустой источник не включает кисть.
- Для каждого атрибута кисть хранит set/clear/keep: одинаковый присутствующий стиль у всего источника → set; стиль отсутствует во всём источнике → clear; источник неоднороден → keep, не менять этот атрибут цели. Поэтому перенос источника «только Bold» на «только Italic» делает цель Bold и снимает Italic; разные цвета внутри источника не меняют цвет цели. Аналогичные правила для цвета/фона и u/sup/sub; mutually exclusive sup/sub нормализуются.
- Сброс части цветного span корректно делит диапазон; повторное применение не наращивает бессмысленные вложения. Литерал <LS_BEN> остаётся видимым текстом.

### Вставка, clipboard, текстовые инструменты

Ссылки используют имеющиеся подсказки заметок; формы дают URL/текст, тип callout, язык fenced code, строки/колонки таблицы. Таблица вставляется стандартным Markdown; полноценный Excel-подобный редактор и сторонний table plugin — отдельные интеграции.

Attach File использует существующий upload и путь attachments относительно заметки. Файл вставляется только в исходный документ; смена вкладки/текста отменяет вставку ссылки, сохраняя сообщение о загруженном файле. Undo убирает ссылку, не удаляет физический файл, который может использоваться в других местах.

Clipboard API проверяется в рантайме. На HTTP-сервере с insecure origin отсутствие доступа объясняется рядом с действием; предлагаются Ctrl/Cmd+C/X/V или поле ручной вставки. Cut не удаляет текст до успешной записи clipboard. Ошибка чтения не стирает выделение.

Для всех 15 текстовых инструментов стандартного набора сначала снять fixtures upstream (полная/половинная ширина, split, merge, trim, dedupe, нумерация, конверсия list/table, извлечение и др.). Использовать текущий явный selection, preview diff для преобразований с параметрами, Apply одной транзакцией. Разделители строк/Unicode/табуляция/пустые строки проверяются отдельно. Параметры извлечения — буквальные строки; произвольный regex не нужен стандартному набору и не добавляется скрыто.

### Расположение, внешний вид, настройки

Поддержать top, following selection, fixed, mobile; включение независимо, свой состав для каждого режима. По умолчанию top + following, mobile адаптируется отдельно. Fixed выключен, чтобы не создавать дубликат без запроса. Настройки: иконки из существующего набора, подписи, подсказки, размер, плотность, перенос/overflow, видимость, порядок, разделители, группы, стандартный/компактный стиль, theme-based/custom цвета панели. Позиция fixed сохраняется относительно viewport и ограничивается его границами.

Конфигурация JSON version=1, сохраняется через существующий settings API. Группы ограничены глубиной 3, суммарно до 200 элементов на раскладку; сломанный раздел восстанавливается из default без сброса auth/vault/прочих настроек. Перестановка мышью и клавиатурой; Reset отдельной раскладки; экспорт/import собственной конфигурации.

customCommands — массив до 100 записей {id,label,icon,prefix,suffix}; id с префиксом custom:, уникален; label до 120 символов, prefix/suffix до 4096 символов, icon из allowlist. Применение буквально окружает каждый выбранный диапазон; пустой диапазон вставляет обе строки с кареткой между ними. Один Undo; шаблон не интерпретирует переменные, JS или regex.

Опциональный импорт выбранного пользователем data.json Editing Toolbar: известные ID переводятся в нативные, порядок/группы/цвета сохраняются, дубликаты отображаемых кнопок допустимы с отдельными instanceId. Неизвестные команды сохраняются как disabled-пункты с причиной и попадают в отчёт. Иконки вне известного набора заменяются безопасной стандартной. Произвольные JS, CSS и SVG из конфигурации не исполняются. Пользовательские текстовые шаблоны можно перенести как буквальные prefix/suffix.

Сторонние Obsidian plugin commands, PKMer login/sync, AI completion/rewrite/Canvas не являются частью основной поставки: это отдельные адаптеры/проекты с собственными настройками и проверками. Не выдавать их за работающие кнопки. Плагин имеет MPL-2.0; при переносе исходных файлов соблюдать условия и атрибуцию. Предпочтителен собственный код на существующих примитивах проекта.

## Приёмка и ограничения проекта

- 64/64 стандартные команды сопоставлены, реализованы и имеют проверку результата либо явное ограничение платформы с рабочим fallback. Неподдерживаемую стандартную команду нельзя засчитать реализованной.
- Все группы открываются, все действия из подпанелей работают; форма Cancel не меняет документ.
- Сопоставить оба пользовательских скриншота с окончательной компоновкой. Личный data.json может уточнить внешний вид, но не блокирует стандартную поставку.
- Все поддерживаемые режимы рендерят одинаковую семантику; Save/Reload/Undo/Redo сохраняют документ.
- Desktop Chromium/Edge, Firefox и Safari по доступности; mobile 390 px, landscape и zoom 200%. Недоступный браузер записать как непроверенный, не объявлять полный pass.
- Регрессии: locked note, переключение вкладки при открытом меню, изменение документа во время диалога/upload, <LS_BEN>, attachment paths и настройка существующего пользователя.
- TypeScript/React/CodeMirror 6 и JSON settings; Node >=22.12.0. Новые runtime зависимости по умолчанию не требуются.
- Существующие параллельные изменения сохраняются; перед сборкой повторно сверить diff и законченные работы. Не включать в выпуск незавершённые правки только потому, что они в общей директории.
- Git commit/push только по явному запросу пользователя. Текущая работа — документы. Будущий deploy использует отдельно согласованный runbook оператора, backup и rollback, включает законченные параллельные доработки.
