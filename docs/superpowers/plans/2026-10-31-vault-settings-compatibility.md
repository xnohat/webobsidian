# План исправления настроек хранилища

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [x]`) syntax for tracking.

**Goal:** Обеспечить предсказуемую работу настроек хранилища, сохранность ссылок и согласованное поведение удаления в WebObsidian.

**Architecture:** Единый серверный слой вычисляет эффективные настройки конкретного хранилища и источник каждого значения. Файловые операции используют эти настройки внутри существующей очереди mutations; интерфейс показывает фактически применённые значения. Настройки представления WebObsidian остаются отдельными от политики файлов Obsidian.

**Tech Stack:** TypeScript, Express, React, Zustand, CodeMirror, Vitest, node:test, существующий Electron browser-test harness.

**Spec:** Запросы пользователя от 2026-10-31, повторная проверка ниже, `PRD.md` FR-1/FR-2 и запись аудита в `IMPLEMENTATION_PLAN.md`. Этот документ задаёт предлагаемый контракт для последующей реализации; реализация и изолированная проверка завершены 2026-10-31.

## Повторная проверка и границы выводов

1. **Подтверждено выполнением:** при `alwaysUpdateLinks:true` переименование `audit/target.md` в `audit/renamed.md` оставляет `[[target]]` и `[Target](target.md)` неизменными в другой заметке. Это не просто отсутствие импорта параметра: необходимого действия действительно нет.
2. **Подтверждено выполнением клиентского сценария:** ошибка `api.references()` заменяется пустым списком, после чего подтверждение диалога приводит к запросу окончательного удаления. Сбой проверки не доказывает отсутствие других ссылок.
3. **Подтверждено кодом и сценарием:** `deleteEmbeddedImage` передаёт `permanent=true`, обходя выбранную корзину. Это не скрытое удаление — текущий диалог предупреждает о необратимости, но настройка «When deleting a file» не является общей для всех действий.
4. **Подтверждено кодом:** при ошибке сохранения режима удаления/retention интерфейс не откатывает показанное значение и не обрабатывает ошибку. Сервер публикует новый settings cache до успешной записи на диск; это отдельная проблема согласованности, а не совместимости с Obsidian.
5. **Подтверждено отсутствие интеграции:** из `app.json` сейчас читается только `attachmentFolderPath`. Отсутствие чтения остальных параметров не означает отсутствие самой функции: например, подтверждение удаления, перенос файлов в корзину и мобильная панель уже существуют, но управляются правилами WebObsidian.
6. **Проверено повторно на временном хранилище:** смена vault.path, обычное удаление, permanent, retention=0, удаление просроченной корзины работают. Очистка после изменения retention запускается асинхронно, поэтому её результат проверяется с ожиданием. Команды reconcile/rebuild принимаются; более широкая проверка выполнения покрывается тестами coordinator.
7. **Исправлено и развёрнуто ранее:** папка вложений, относительные ссылки, видимость старых `attachments`, включая ` attachments` с ведущим пробелом. Отдельный browser test проверяет checkbox Settings вместе с FileTree и auto-reveal. Повторно реализовывать эти изменения не требуется.
8. **Новая подтверждённая HTTP-регрессия:** для файла `shot #1 (a).png` с вставленной ссылкой `shot%20%231%20%28a%29.png` endpoint references возвращает пустой список, хотя другая заметка содержит эту ссылку. Причина — ранний текстовый фильтр распознаёт только raw-имя и `%20`; аналогичная ошибка есть в счётчике ссылок текущего документа. Кодирование пути загрузчиком корректно, исправлять нужно распознавание ссылок, а не убирать кодирование.
9. **Новая подтверждённая HTTP-регрессия:** PUT settings с `vault.path=""` получает 200, сохраняет пустую строку и выбирает process.cwd(). Проверка выполнена с рабочим каталогом процесса внутри временной тестовой папки. Текущий `if (... && path)` пропускает валидацию пустого пути.

Официальная сверка: [Settings](https://obsidian.md/help/settings), [Internal links](https://obsidian.md/help/links). Существенные уточнения: выключенное автоматическое обновление ссылок требует вопроса пользователю; исключения относятся к поиску/графу/несвязанным упоминаниям и ранжированию подсказок, а не запрету чтения или скрытию дерева файлов. Системная корзина клиента недоступна серверному веб-приложению.

## Ограничения

- Сохранить существующие исправления вложений; выпускать изменения через проверяемую ветку и PR.
- Разработка и тесты — на синтетических хранилищах. Не мигрировать существующие вложения и не переписывать реальные заметки в рамках проверки.
- Не менять `.obsidian/app.json` при чтении или нормализации; неизвестные ключи сохраняются. Поддержка другого config folder — отдельное расширение, не предполагать её автоматически.
- `vault.path`, allowedRoots, ресурсы сервера, retention и данные авторизации управляются WebObsidian/оператором, не импортируются из Obsidian.
- Ни системная корзина, ни ошибка чтения настроек не должны превращаться в permanent delete.
- Нельзя скрывать проблему сохранения через оптимистическое обновление UI или settings cache.
- Развёртывание выполняется по отдельно согласованному плану с резервной копией и проверяемым откатом.
