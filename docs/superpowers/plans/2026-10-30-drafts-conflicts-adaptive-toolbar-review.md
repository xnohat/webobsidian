# Ревью панели, черновиков и конфликтов — 2026-10-30

Область: адаптивная панель, IndexedDB-журнал, восстановление, разрешение конфликтов и привязка браузерных операций к vault. Предыдущие изменения аутентификации/файловой системы не откатывались. Независимый рецензент работал только на чтение; исправления выполнялись в текущем checkout. Коммитов и развёртывания не было.

## Найденные и исправленные проблемы

| Приоритет | Проблема | Исправление и доказательство |
|---|---|---|
| P1 | Повторное открытие файла сбрасывало revision при прежнем writerId; новый текст мог не заменить оставшуюся старую запись | Новая идентичность сессии документа при каждом открытии. Тест `reopening a document uses a fresh journal identity` сначала падал, затем прошёл |
| P1 | После успешного разрешения конфликта удалялась живая сессия; отказ последующего GET оставлял новые правки без журнала | Подтверждённый текст и version применяются к живой сессии без обязательного GET. Браузерный тест запрещает последующее чтение и проверяет сохранение новой правки в IndexedDB |
| P1 | Старое окно/запрос восстановления переживали смену vault; возможна запись текста A в файл B | Epoch-проверки, немедленная очистка UI, отказ устаревших compare/refresh. GET/PUT принимают `draftScopeId` и проверяют его внутри операции с захваченными настройками vault. Серверный RED→GREEN проверяет одинаковые версии файлов в разных vault |
| P1 | Обычный GET мог прочитать новый vault, а журнал получить cached scope старого | Scope захватывается перед чтением и передаётся в GET. При отказе определения scope редактор не откатывается к unscoped-чтению; отказ IndexedDB при известном scope по-прежнему допускает ручное серверное сохранение. Проверено отдельным lifecycle-тестом; сервер отказывает несовпадающему scope |
| P2 | Ошибка очистки IndexedDB после успешного PUT изображалась как ошибка серверного сохранения | Серверное подтверждение возвращается независимо от cleanup; ошибки очистки показываются отдельным уведомлением. Реальный браузерный тест внедряет отказ `IDBObjectStore.delete` |
| P2 | Запоздалый ответ автосохранения заменял уже принятую новую базовую версию | Поколение подтверждения проверяется до запроса, после ответа и во время cleanup. RED→GREEN для позднего ответа и принятия результата во время local flush |
| P2 | Ввод во время cleanup помечался как полностью сохранённый | После cleanup повторно проверяется revision; новая редакция записывается локально и не получает статус saved. Отдельный RED→GREEN |
| P2 | Статус, меню, палитра и окно конфликтов уходили под мобильную клавиатуру | Общая геометрия visualViewport; ограничение размеров и координат всплытий; окно конфликтов ограничено видимой областью. До исправления проверки воспроизводили скрытие статуса, палитры и диалога |
| P2 | Меню при открытии измерялось до применения min/max размеров и на короткое время выходило за правый край | Ограничения применяются до измерения; размещение в layout effect. Старый browser-тест воспроизвёл `right=422` при viewport 390; после исправления прошёл |
| P2 | Fixed-панель выходила за экран; ширина ручки перемещения не учитывалась | Удалён transformed containing block обёртки, координаты ограничены видимой областью, handle включён в расчёт переполнения. Браузерный RED→GREEN у позиции x/y=0.95 |

При изменении состава overflow открытая ветка закрывается с возвратом фокуса на More. Диалог разрешения конфликта удерживает клавиатурный фокус; Escape сохраняет результат для последующего восстановления.
